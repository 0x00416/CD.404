# CD.404 公开测试版执行计划

> 基线：2026-08-09，代码事实优先于旧文档描述
> 目标：从可用 Alpha 推进到可公开测试、可诊断、可回退的 Windows 10/11 原生版本

## 统一交付门槛

每个阶段采用独立的小批次中文 Conventional Commit，并同时满足：

1. 先补会失败的单元、集成或合成测试，再实现功能。
2. 改动直接相关的测试通过；完整 `make release` 通过；失败时不提交。
3. 光驱、WASAPI、设备移除和电源事件必须经过可注入边界；没有硬件时仍可重复验证。
4. 同步 `docs/IMPLEMENTATION_STATUS.md`，记录真实硬件覆盖、缺失条件和计划调整理由。
5. 不提交 Token、本机路径、本地数据库、缓存、构建产物或诊断中的隐私数据。
6. 共享模式保持默认；独占模式只能显式启用，失败原因和回退结果必须可见。
7. CDDA 读取失败保持严格语义，不伪造、插入或静默修饰音频样本。

## 分阶段计划

### 阶段 1：设备与电源生命周期（已完成自动化门槛）

- 合并播放期间的插盘、拔盘、换盘通知，忙碌时不丢最后一次刷新。
- 介质消失后协作取消读取和 WASAPI，释放完成后再刷新 UI。
- 休眠前保存精确位置并有序停止；唤醒后重新读取 TOC，只对同一张盘自动续播。
- 默认音频端点失效时从已渲染位置重开一次共享会话；连续失败停止重试并显示原因。
- 合成测试覆盖通知分类、刷新合并、换盘禁止自动播放、暂停态唤醒和端点防重试循环。

本机未枚举到可用光驱、介质或音频端点，真实拔盘、端点切换和休眠回归保留到发布候选硬件矩阵；这不替代本阶段已经通过的确定性合成测试。

### 阶段 2：长生命周期播放协调

- 将播放会话改为命令驱动，定位和任意音轨切换不销毁 WASAPI 客户端。
- 重置 CDDA 生产端与环形缓冲时建立明确的代次/屏障语义，禁止旧样本越过定位点。
- 保持相邻音频轨同一连续流，并重复验证跨轨无丢帧、重复、插帧和重排。
- 为随机定位、快速连续切轨、暂停中定位和设备事件竞态增加合成压力测试。

### 阶段 3：输出模式与设备选择

- 枚举稳定的输出端点 ID 和友好名称，设置中保存选择但允许设备消失。
- 协商 44.1 kHz、16 bit、stereo PCM；独占模式仅在设备明确支持时初始化。
- 默认共享模式继续允许 Windows 格式转换；独占失败时解释 HRESULT，并由用户确认或按明确策略回退共享模式。
- 测试格式支持矩阵、端点消失、默认端点变化、独占占用和回退结果。

### 阶段 4：可修订、可追溯的元数据

- 实现标准 MusicBrainz Disc ID 精确查询，保留现有 TOC 模糊匹配作为低置信度候选。
- 展示多个发行版候选，按 Disc ID/TOC 记忆选择，并允许重新选择。
- 使用本地持久缓存支持离线启动、过期刷新和模式迁移。
- 支持手动修订；每个专辑/曲目字段记录用户、CD-TEXT、MusicBrainz、GnuDB 或 iTunes 来源，刷新不得覆盖用户值。

### 阶段 5：ListenBrainz 可靠性

- 定义 `playing_now` 发出后 MusicBrainz ID 迟到时的补充策略，避免重复正式记录。
- 在设置页增加按当前账户清理待同步队列的明确入口，不在播放主界面显示进度。
- 对 SQLite 迁移、重启恢复、账户切换、401、429、5xx 和网络失败建立自动测试。
- 保持 Token 仅在 Windows 凭据管理器或进程环境中，不写数据库和日志。

### 阶段 6：验证基础设施

- 将 HTTP 传输抽象为可替换客户端，提供进程内假客户端或本地模拟服务。
- 增加重复跨轨、随机切换、设备异常与并发取消测试，固定随机种子并输出可复现参数。
- 设计 WASAPI 回环采集验证共享模式；独占模式若无法回环，则提供外部采集步骤和硬件限制说明。
- 区分自动化保证、真实硬件观察和尚未验证的声明。

### 阶段 7：发布工程

- 按播放协调、页面、绘制、设置和元数据拆分 `main_window.cpp`；按存储、HTTP、重试与凭据拆分 `listenbrainz_reporter.cpp`。
- 增加可脱敏诊断日志导出、键盘与屏幕阅读器可达性、系统浅色/深色主题。
- 提供无需管理员权限的每用户安装包方案、程序版本资源和卸载路径。
- 补齐隐私说明、第三方许可、发布检查表、签名/哈希和回滚说明。

## 计划调整记录

- 旧计划将仓库描述为 P0 底层验证，但当前代码已经具备完整原生 UI、进程内播放、SMTC、在线元数据和 ListenBrainz 持久队列，因此里程碑调整为“公开测试版加固”。
- 现有相邻音轨已能在同一播放请求中连续通过，但 UI 主动定位和任意切轨仍会停止并重建会话；阶段 2 聚焦后者，不重复已经完成的连续流基础工作。
- 发布版构建默认不编译诊断 probes；硬件环境检查以系统枚举与现有可执行程序为准，发布候选阶段再建立固定硬件矩阵。
