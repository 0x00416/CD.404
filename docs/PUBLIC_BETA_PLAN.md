# CD.404 公开测试版执行计划

> 基线：2026-08-09，代码事实优先于旧文档描述
> 目标：从可用 Alpha 推进到可公开测试、可诊断、可回退的 Windows 10/11 原生版本

## 统一交付门槛

每个阶段采用独立的小批次中文 Conventional Commit，并同时满足：

1. 先补会失败的单元、集成或合成测试，再实现功能。
2. 改动直接相关的测试通过；完整 `make release` 通过；失败时不提交。
3. 光驱、WASAPI、设备移除和电源事件必须经过可注入边界；没有硬件时仍可重复验证。
4. 同步 `docs/IMPLEMENTATION_STATUS.md`，记录真实硬件覆盖、缺失条件和计划调整理由。
5. 不提交 Token、本机路径、本地数据库、缓存、构建产物或诊断中的隐私数据。
6. 共享模式保持默认；独占模式只能显式启用，失败原因和回退结果必须可见。
7. CDDA 读取失败保持严格语义，不伪造、插入或静默修饰音频样本。

## 分阶段计划

### 阶段 1：设备与电源生命周期（已完成自动化门槛）

- 合并播放期间的插盘、拔盘、换盘通知，忙碌时不丢最后一次刷新。
- 介质消失后协作取消读取和 WASAPI，释放完成后再刷新 UI。
- 休眠前保存精确位置并有序停止；唤醒后重新读取 TOC，只对同一张盘自动续播。
- 默认音频端点失效时从已渲染位置重开一次共享会话；连续失败停止重试并显示原因。
- 合成测试覆盖通知分类、刷新合并、换盘禁止自动播放、暂停态唤醒和端点防重试循环。

本机未枚举到可用光驱、介质或音频端点，真实拔盘、端点切换和休眠回归保留到发布候选硬件矩阵；这不替代本阶段已经通过的确定性合成测试。

### 阶段 2：长生命周期播放协调（已完成自动化门槛）

- 将播放会话改为命令驱动，定位和任意音轨切换不销毁 WASAPI 客户端。
- 重置 CDDA 生产端与环形缓冲时建立明确的代次/屏障语义，禁止旧样本越过定位点。
- 保持相邻音频轨同一连续流，并重复验证跨轨无丢帧、重复、插帧和重排。
- 为随机定位、快速连续切轨、暂停中定位和设备事件竞态增加合成压力测试。

实现按连续音频区间复用会话：普通纯音频 CD 可在任意曲目间前后切换；混合模式跨数据轨时明确返回 `outside_session` 并走安全重建路径。当前环境无光驱和可用端点，已用 128 次确定性跨边界重定位逐帧验证旧缓冲清除及目标帧连续性；同一真实 WASAPI 客户端的硬件观察保留到发布候选矩阵。

### 阶段 3：输出模式与设备选择（已完成自动化门槛）

- 枚举稳定的输出端点 ID 和友好名称，设置中保存选择但允许设备消失。
- 协商 44.1 kHz、16 bit、stereo PCM；独占模式仅在设备明确支持时初始化。
- 默认共享模式继续允许 Windows 格式转换；独占失败时解释 HRESULT，并由用户确认或按明确策略回退共享模式。
- 测试格式支持矩阵、端点消失、默认端点变化、独占占用和回退结果。

执行批次：

1. 先提取不依赖真实端点的输出模式、格式协商、错误解释与回退决策模型，并用假端点覆盖支持、占用、消失和初始化失败矩阵。
2. 接入真实 MMDevice 枚举、稳定端点 ID、指定设备打开和独占初始化；共享模式仍为默认，独占失败只按显式设置回退并保留原因。
3. 持久化输出设备、模式与回退策略，在设置页展示当前结果和端点失效状态；验证停止、重置、COM 接口和句柄的释放顺序。

实现已接入真实 MMDevice 枚举与稳定端点 ID，设置页可选择系统默认或具体端点并持久化。共享模式保持默认；独占模式先调用 `IsFormatSupported` 精确确认 44.1 kHz/16 位/双声道 PCM，再按设备周期初始化。格式不支持、设备占用、设备失效和音频服务异常均提供可解释文本；共享回退只有用户显式启用时发生，并同时保留原始独占失败原因和实际模式。当前环境没有可用音频端点，真实独占初始化、端点切换和释放顺序观察保留到发布候选硬件矩阵；策略和错误矩阵已由可注入假后端确定性覆盖。

### 阶段 4：可修订、可追溯的元数据（已完成自动化门槛）

- 实现标准 MusicBrainz Disc ID 精确查询，保留现有 TOC 模糊匹配作为低置信度候选。
- 展示多个发行版候选，按 Disc ID/TOC 记忆选择，并允许重新选择。
- 使用本地持久缓存支持离线启动、过期刷新和模式迁移。
- 支持手动修订；每个专辑/曲目字段记录用户、CD-TEXT、MusicBrainz、GnuDB 或 iTunes 来源，刷新不得覆盖用户值。

执行批次：

1. 实现标准 MusicBrainz Disc ID 计算、精确 `/ws/2/discid/` 查询和多发行版解析；仅在精确结果不可用时保留现有 TOC 模糊查询。
2. 建立与 UI 解耦的候选选择、字段级来源和“用户值优先”合并模型，并测试选择记忆、重新选择及刷新保护。
3. 增加带版本号的本地持久缓存，覆盖命中、过期、损坏与迁移；UI 接入候选选择、手动修订和来源呈现。

实现保留精确 Disc ID 命中的全部时长兼容发行版，并按本地记忆优先选择；播放器可按 `M` 重新选择。字段模型逐项记录用户、CD-TEXT、MusicBrainz、GnuDB、iTunes 或未知来源，来源摘要在主界面呈现。`F2`/`Shift+F2` 修订当前曲名/表演者，`Ctrl+F2`/`Ctrl+Shift+F2` 修订专辑名/专辑艺术家；用户值写入版本化本地缓存并在刷新时保持最高优先级。缓存支持离线加载、损坏回退、过期判断与旧无版本格式迁移。

### 阶段 5：ListenBrainz 可靠性（已完成自动化门槛）

- 定义 `playing_now` 发出后 MusicBrainz ID 迟到时的补充策略，避免重复正式记录。
- 在设置页增加按当前账户清理待同步队列的明确入口，不在播放主界面显示进度。
- 对 SQLite 迁移、重启恢复、账户切换、401、429、5xx 和网络失败建立自动测试。
- 保持 Token 仅在 Windows 凭据管理器或进程环境中，不写数据库和日志。

执行批次：

1. 把 HTTP 和时间/重试边界改为可注入接口，以脚本化假客户端覆盖 401、429、5xx、网络失败及成功恢复。
2. 为队列模式迁移、重启恢复和账户隔离补自动测试，增加只清理当前账户待同步记录的 API 与设置页入口。
3. 固化迟到 MBID 策略：若 `playing_now` 已发送且身份随后补全，发送一次带稳定会话标识的更新；正式 `single` 仍仅入队一次。

实现采用一次性修正策略：首个 `playing_now` 可不含尚未到达的 MBID；首个 MusicBrainz 身份随后到达时只补发一次 `playing_now`，后续身份补全不再重复修正，正式 `single` 仍仅持久入队一次。SQLite 队列已升级到 v3 并按不可逆账户指纹隔离；设置页可只清理当前账户的待同步记录，播放主界面保持无上报进度。上报器接受可注入 HTTP 客户端和队列路径，脚本化测试覆盖迁移、重启、账户隔离、401、429、503 和网络失败且不访问公网。

### 阶段 6：验证基础设施

- 将 HTTP 传输抽象为可替换客户端，提供进程内假客户端或本地模拟服务。
- 增加重复跨轨、随机切换、设备异常与并发取消测试，固定随机种子并输出可复现参数。
- 设计 WASAPI 回环采集验证共享模式；独占模式若无法回环，则提供外部采集步骤和硬件限制说明。
- 区分自动化保证、真实硬件观察和尚未验证的声明。

执行批次：

1. 复用阶段 3/5 的可注入边界，增加固定种子的跨轨、任意切轨、定位、取消与设备异常组合压力测试。
2. 提供可执行的 WASAPI 共享模式回环检查工具和独占模式外部采集步骤；没有端点时明确报告跳过条件而不是成功。
3. 将自动化、真实硬件观察和发布候选硬件矩阵分别记录，保留失败复现种子与运行命令。

### 阶段 7：发布工程

- 按播放协调、页面、绘制、设置和元数据拆分 `main_window.cpp`；按存储、HTTP、重试与凭据拆分 `listenbrainz_reporter.cpp`。
- 增加可脱敏诊断日志导出、键盘与屏幕阅读器可达性、系统浅色/深色主题。
- 提供无需管理员权限的每用户安装包方案、程序版本资源和卸载路径。
- 补齐隐私说明、第三方许可、发布检查表、签名/哈希和回滚说明。

执行批次：

1. 在行为测试保护下拆分播放协调/设置/元数据 UI 与 ListenBrainz 存储/传输/重试职责，保持公共行为不变。
2. 增加脱敏诊断事件模型与导出、键盘焦点/可访问名称、系统高对比度及浅色/深色主题响应。
3. 增加每用户安装/卸载脚本、程序版本资源、隐私说明、第三方许可和发布检查表，并把静态检查、测试、哈希、签名与回滚步骤纳入发布门禁。

## 计划调整记录

- 旧计划将仓库描述为 P0 底层验证，但当前代码已经具备完整原生 UI、进程内播放、SMTC、在线元数据和 ListenBrainz 持久队列，因此里程碑调整为“公开测试版加固”。
- 阶段 2 已把 UI 主动定位和任意切轨接入长生命周期会话；混合模式跨数据轨时才显式走安全重建路径。后续压力测试只补强并发和重复性，不重做该能力。
- 发布版构建默认不编译诊断 probes；硬件环境检查以系统枚举与现有可执行程序为准，发布候选阶段再建立固定硬件矩阵。
