- 连续流支持任意采样帧位置定位，不需要在轨道边界重建数据源。
- 使用合成递增帧序列验证跨轨读取无漏帧、插帧和重复帧。
- 使用 `IOCTL_CDROM_RAW_READ` 和 CDDA 模式实现 Windows 原始音频扇区读取。
- 实现原始 CDDA 读取诊断探针。
- 添加基础单元测试并接入 CTest。

## 本次验证结果

- CMake 使用 Ninja/MSVC 成功配置。
- MSVC Debug 构建成功。
- CTest：1/1 测试程序通过，覆盖时间转换、边界、溢出和 TOC 验证场景。
- 已验证系统光驱枚举能力。
- 无介质时 TOC 读取返回“设备未就绪”；该错误路径工作正常。
- 使用真实音频 CD 成功读取 TOC 和原始 CDDA 数据。
- 原始读取一次成功取得 16 个扇区，共 37,632 字节。
- 连续流在真实光盘上成功跨越相邻音轨读取三个采样帧，期间未重建扇区源。
- 合成跨轨测试使用不规则读取块通过轨道边界，并逐帧验证完整序列。

受限自动化环境可能阻止 MSBuild FileTracker 访问部分系统资源；遇到这种情况可使用 Ninja/MSVC 预设。该限制不影响普通开发终端使用 Visual Studio 生成器预设。
