# 实施状态

> 更新时间：2026-08-06

## 当前里程碑

P0：底层技术验证。

## 已完成

- 初始化 C++20/CMake 工程。
- 添加 Visual Studio 2026 x64 和 Ninja/MSVC 构建预设。
- 添加空的 vcpkg manifest，为后续按项目锁定第三方依赖预留入口。
- 实现 CDDA 常量及 MSF、绝对扇区、LBA、采样帧转换。
- 实现转换范围和乘法溢出检查。
- 实现平台无关 TOC 模型、轨号连续性、轨道位置和 lead-out 验证。
- 从 TOC 自动计算轨道结束 LBA、整盘起始采样帧和轨道采样帧数。
- 实现 Windows 光驱枚举。
- 使用 `IOCTL_CDROM_READ_TOC_EX` 读取原生 TOC 并转换为平台无关模型。
- 实现命令行光驱探针。
- 定义平台无关的 CDDA 扇区源接口。
- 实现带 16 扇区内部缓存的整盘连续 CDDA 流。
- 连续流支持任意采样帧位置定位，不需要在轨道边界重建数据源。
- 使用合成递增帧序列验证跨轨读取无漏帧、插帧和重复帧。
- 使用 `IOCTL_CDROM_RAW_READ` 和 CDDA 模式实现 Windows 原始音频扇区读取。
- 实现原始 CDDA 读取诊断探针。
- 确认 Windows 原始 CDDA 数据可直接按 PCM16LE 使用，并实现显式格式适配接口。
- 实现事件驱动的 WASAPI 共享模式输出，输入格式固定为音频 CD 原生的
  44.1 kHz、16 位、双声道 PCM。
- 实现最小播放探针：自动选择已就绪的音频 CD，可指定音轨和播放时长。
- 实现预分配的有界 SPSC PCM16 环形缓冲，生产和消费操作均不分配内存、不阻塞。
- 将光盘读取移至独立生产线程，以约 6 秒缓冲和 1 秒首播水位隔离光驱抖动。
- 播放范围可覆盖连续音频轨区间；轨道边界不重建扇区源、连续流或 WASAPI 会话。
- 增加 `--all`、音轨内起始偏移和 `Ctrl+C` 取消；取消可中断 WASAPI 事件等待。
- 原始 CDDA 读取改用 Windows 重叠 I/O，取消时通过 `CancelIoEx` 中断待处理读取。
- WASAPI 输出改为预填后显式启动，正常 EOS 才排空，取消和错误直接停止。
- 消费端检查 WASAPI padding；非 EOS 状态耗尽端点缓冲会记录为欠载失败。
- 添加基础单元测试并接入 CTest。

## 本次验证结果

- CMake 使用 Ninja/MSVC 成功配置。
- MSVC Debug 构建成功。
- CTest：1/1 测试程序通过，覆盖时间转换、边界、溢出和 TOC 验证场景。
- 已验证系统光驱枚举能力。
- 无介质时 TOC 读取返回“设备未就绪”；该错误路径工作正常。
- 使用真实音频 CD 成功读取 TOC 和原始 CDDA 数据。
- 原始读取一次成功取得 16 个扇区，共 37,632 字节。
- 连续流在真实光盘上成功跨越相邻音轨读取三个采样帧，期间未重建扇区源。
- 合成跨轨测试使用不规则读取块通过轨道边界，并逐帧验证完整序列。
- PCM 格式测试覆盖有符号边界样本、帧对齐、目标缓冲区容量和空输入。
- 使用真实音频 CD 完成从原始扇区读取、PCM 适配到默认 WASAPI 端点的 5 秒试播，
  所有请求帧均已写入并正常排空。
- 环形缓冲测试覆盖环绕、部分传输、满/空/EOS/reset，并发传输 50,000 帧时逐帧
  验证无丢失、重复和重排。
- 使用 6 秒有界缓冲完成 8 秒实体光盘流式播放，共提交 352,800 帧，验证不依赖
  整段预读。
- 从实体光盘某音轨边界前开始播放并越过边界，共连续提交 264,600 帧；期间保持
  同一个 CDDA 连续流和 WASAPI 会话。

受限自动化环境可能阻止 MSBuild FileTracker 访问部分系统资源；遇到这种情况可使用 Ninja/MSVC 预设。该限制不影响普通开发终端使用 Visual Studio 生成器预设。
